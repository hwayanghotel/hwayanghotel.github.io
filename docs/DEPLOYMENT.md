# 배포와 운영 안내

2026-10-05 GitHub Pages 배포 구성. [공개 주소](https://hwayanghotel.github.io/)에 `dist/`만 배포합니다. 자체 API 서버·DB·서버리스 함수·비밀키는 필요하지 않습니다. 기존 운영 사이트와 도메인은 이번 작업에서 변경하지 않았습니다.

## 배포 파일

```bash
npm ci
npm run check
npm run build
```

정적 호스팅의 build command는 `npm run build`, output directory는 `dist`, Node는 22.12 이상으로 설정합니다. HTML·CSS·JS·이미지·글꼴·라이선스·사이트맵을 함께 배포합니다. `research/`, 조사 JSON, 개발 패키지와 미디어 원본 아카이브는 공개 경로에 넣지 않습니다.

현재 링크는 도메인 루트(`/`) 배포를 전제로 합니다. GitHub Pages 사용자 사이트나 사용자 지정 도메인에 맞으며 프로젝트 하위 경로 배포에는 base 경로 변경이 필요합니다. 별도 분석 도구나 쿠키는 삽입하지 않았습니다.

## GitHub Pages 자동 배포

소스는 `main`, 게시용 HTML과 자산은 `gh-pages`에 보관합니다. 저장소 Settings → Pages의 기존 설정인 **Deploy from a branch / gh-pages / root**를 유지합니다.

`.github/workflows/pages.yml`은 `main` 푸시 또는 수동 실행으로 다음을 수행합니다.

1. Node 22에서 `npm ci`, `npm run check`, `npm run build`를 실행합니다.
2. `dist/`를 `.nojekyll`과 함께 `gh-pages`에 일반 커밋으로 게시합니다. 강제 푸시는 하지 않습니다.
3. GitHub Pages REST API로 빌드를 요청합니다. 워크플로 토큰의 푸시만으로는 후속 배포가 시작되지 않을 수 있어 명시적으로 요청합니다.

워크플로는 기본 `GITHUB_TOKEN`의 `contents: write`, `pages: write` 권한을 사용합니다. 별도 토큰이나 서버를 등록할 필요가 없습니다. `main` 또는 `gh-pages`의 보호 규칙을 추가한다면 배포 워크플로의 게시 권한도 함께 조정해야 합니다.

[Actions 실행 기록](https://github.com/hwayanghotel/hwayanghotel.github.io/actions)과 Settings → Pages에서 배포 상태를 확인합니다. 소스 커밋을 되돌려 `main`에 푸시하면 같은 경로로 재배포됩니다. 기존 Angular 소스와 게시 파일의 이력은 그대로 남아 있습니다.

## 도메인과 지도

현재 공개 주소는 `https://hwayanghotel.github.io`입니다. 도메인을 바꾸면 `astro.config.mjs`, `src/data/site.ts`, `public/robots.txt`와 `tests/site.spec.ts`의 기대 주소를 함께 수정합니다. 기존 URL 호환 페이지의 canonical은 `site.url`에서 생성됩니다. 페이지마다 title·description·canonical·OG, 한국어 lang, 숙박업 구조화 데이터가 있습니다. 사이트맵은 주요 10페이지를 포함합니다.

네이버·카카오 지도는 ‘화양계곡 능운대펜션’을 검색하는 링크입니다. 실제 주차장 좌표를 검증하지 못해 임의의 경로 목적지를 만들지 않았습니다. 지도 SDK와 API 키가 없습니다.

## 이전 URL

`public/_redirects`는 Netlify 방식의 리다이렉트를 지원하는 호스팅용입니다. 다른 호스팅에서는 해당 서비스의 규칙으로 바꿉니다. 한글 Wix URL의 인코딩된 요청도 배포 환경에서 검증합니다.

GitHub Pages처럼 임의의 서버 301을 지원하지 않는 환경을 위해 구 경로에 호환 HTML도 생성합니다. meta refresh·실제 목적지 링크·새 경로의 canonical이 있으며 **HTTP 301 응답과는 다릅니다.**

`#/room`, `#/food`, `#/location`, `#/story`, `#/landing`, `#/home`, `#/booking-food`는 루트에서 작은 클라이언트 스크립트로 연결합니다. 해시 부분은 서버로 전달되지 않습니다. 폐지 서비스·관리자 경로와 블로그 전체를 임의로 홈으로 보내지 않습니다.

알 수 없는 주소는 실제 404 상태와 커스텀 `404.html`을 반환하도록 설정합니다. SPA용 `/* /index.html 200` 재작성은 사용하지 않습니다. 각 상세 경로는 독립 HTML이며 직접 진입과 새로고침이 가능합니다.

## 콘텐츠 수정

연락처·객실·FAQ는 `src/data/site.ts`, 메뉴는 `src/pages/dining.astro`, 차량 안내는 `src/pages/visit.astro`를 수정합니다. 전화·주소를 바꾸면 SEO 설명에도 이전 값이 남지 않도록 검색합니다.

사진은 `src/assets/photos`에 추가하고 `src/data/asset-sources.json`에 파일·한국어 alt·출처를 등록합니다. `npm run assets`가 원본 변경 시각을 확인해 WebP를 생성합니다. 원본보다 확대하지 않습니다. 저해상도 객실 사진은 재촬영본으로 교체하는 것이 가장 큰 품질 개선입니다.

공식 Pretendard 가변 서브셋만 자체 제공하며 라이선스 파일을 함께 유지합니다. 마루부리는 이전 시안 아카이브에 보존하고 현재 배포에서 제외했습니다. 생성되는 서비스 이미지는 WebP, 공유 이미지는 JPEG입니다. AVIF를 필수로 추가하지 않고 단순한 정적 빌드를 유지했습니다.

## 배포 후

HTTPS·canonical 주소, 상세 직접 진입, 예약 숙소 ID, 전화·지도 이동, 301/404, 모바일 하단 예약 영역을 확인합니다. 실제 iOS Safari·Android Chrome의 전화·지도 앱 전환은 실기기에서 별도 확인합니다. 로컬 Chromium 에뮬레이션은 실기기 검사를 대신하지 않습니다.

새 호스팅 검증과 URL 대응을 마친 뒤 도메인을 전환합니다. 기존 Wix를 먼저 폐쇄하지 않습니다. 공개 미리보기의 검색 노출 여부도 호스팅 단계에서 관리합니다.
